   Gmail may be parsed in a later phase.
2. Auto-submission only for email applications; for web forms we prepare
   everything and I submit manually.
3. Only the official/public APIs and RSS feeds listed below.

   re-prioritize content from data/cv-master.md. Respect its "known

5. Tailored CVs must be ATS-friendly: single column, standard headings
   (Experience, Skills, Education), no tables/graphics/icons,
   .docx + text-extractable PDF.
6. This repo is PRIVATE (personal data). Never commit .env; .gitignore
   must cover .env*, output/, node_modules, data/state.

## DB schema (Drizzle, Postgres)
Table `jobs`: id uuid pk, company, role, url unique, source,
description text, score int, verdict, matched_keywords jsonb,
missing_keywords jsonb, red_flags jsonb, timezone_fit, salary_info,
location_policy, status enum (new|shortlisted|tailored|applied|
screening|interview|offer|rejected|archived), date_found, date_applied,
follow_up_due timestamps, notes text, content_hash unique, created_at,
updated_at.
Table `seen_hashes`: hash pk, first_seen — archived jobs never resurface.
Table `companies`: slug pk, ats enum (greenhouse|lever|ashby), added_from.

## Pipeline stages
1. Fetch all sources in parallel → normalize to one zod-validated Job
   type: {company, role, url, source, description, salary_info,
   location_policy, posted_at}.
2. Dedupe: content_hash = sha256(normalized company+title); fuzzy title
   match for near-duplicates; skip anything present in seen_hashes.
3. Hard filters (code, no LLM): reject if title lacks
   frontend|front-end|react|ui engineer|web engineer|fullstack(+react
   in description); reject if text contains hybrid|on-site|onsite|
   US only|must be located in|US work authorization|W2|relocation
   required (for DOU also: office-bound wording, "офіс"); reject
   junior/intern; reject older than 21 days. When unsure — KEEP
   (false negatives are worse than false positives).
4. LLM scoring (via LlmScorer → `claude -p`, batched) against
   data/cv-master.md → strict JSON:
   { score: 0-100, matched_keywords: [], missing_keywords: [],
     red_flags: [], timezone_fit: "good|ok|bad", one_line_verdict: "" }
   score >= 65 → insert status "new"; below → seen_hashes only.
5. Digest: if new jobs were inserted, email me via Resend — top matches
   with scores, verdicts, and dashboard links.

## Skills (.claude/skills/)
1. find-jobs — run the full pipeline locally, print funnel numbers
   (fetched → deduped → filtered → scored → inserted).
2. score-job — score a single pasted URL/JD (from Djinni/Wellfound/
   LinkedIn alert emails etc.) and insert into the DB.
3. tailor-application — given a job id: tailored CV (.docx + PDF) +
   cover letter + standard form answers (salary, notice period, work
   auth, timezone), saved to output/applications/{company}-{role}/,
   status → tailored. Use the emphasis presets and "known gaps" section
   from cv-master.md. ATS rules from Hard Constraints apply.
4. follow-up — list applications 7+ days after applying with no
   response, draft polite follow-up emails.
